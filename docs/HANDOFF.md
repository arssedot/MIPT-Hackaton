# Передача проекта разработчику

Репозиторий содержит исходный код, миграцию, lock-файл, контейнеры, тесты и документацию. Предоставленные организаторами документы и локальные секреты передаются отдельно и не должны попадать в публичную историю Git.

## Проверка чистого окружения

1. Получить репозиторий и открыть его корень.
2. Установить Node.js версии из `.nvmrc`, Docker Engine / Desktop и Compose v2.
3. Выполнить `npm run setup`, затем `docker compose up --build -d --wait --wait-timeout 240`.
4. Проверить `http://localhost:3000/api/health/ready` и войти на `http://localhost:3000` с паролем из `.local/access.txt`.
5. Выполнить оба сценария из README, перезапустить приложение и убедиться, что история сохранилась.
6. При необходимости добавить ключ провайдера, модель, включить внешний анализ и проверить открытый синтетический документ. API без ключа отдельно не считается протестированным.

## Перенос на сервер

Сначала воспроизведите локальный Compose. На сервере заново сгенерируйте секреты: не используйте локальный пароль в production. В `.env` задайте точный HTTPS-origin сервера и `COOKIE_SECURE=true`. Разместите Caddy/Nginx с TLS перед loopback-портом 3000. Не публикуйте PostgreSQL в Интернет. Установите ограничение тела запроса 9 МБ и timeout прокси более 100 секунд. Если reverse proxy работает отдельным контейнером, подключите его к внутренней сети и направьте на `app:3000`, адаптировав Compose в отдельном override-файле.

Общий пароль не предназначен для многопользовательского публичного сервиса. До такого открытия добавьте персональную аутентификацию, права доступа к документам, общий limiter и журнал действий. Сейчас приложение предназначено для локальной демонстрации и команды, которой доверен общий кабинет.

CI намеренно не подключён к серверу: нет VPS, SSH-ключа, домена, образов в реестре и автоматической доставки. На новом сервере можно использовать текущую сборку Compose. Не добавляйте выдуманные SSH-адреса или ключи для прохождения workflow. Если понадобятся образы, добавьте отдельный job публикации в GHCR с минимальными правами, после успешных тестов.

## Секреты

Обязательные значения создаёт `scripts/setup.mjs` и сохраняет в `.env`; пароль входа дополнительно записывается в `.local/access.txt`. Они исключены из Git. Скрипт `sync-secrets.mjs` дублирует непустые ADMIN_PASSWORD, SESSION_SECRET, POSTGRES_PASSWORD, LLM_API_KEY в GitHub Actions Secrets с использованием авторизованного `gh`. Эти значения не нужны текущему CI и не используются в тестах.

Смена ADMIN_PASSWORD запрещает новые входы по старому паролю; смена SESSION_SECRET аннулирует все существующие сессии. После изменения окружения пересоздайте контейнер приложения. POSTGRES_PASSWORD нельзя просто поменять в `.env` при существующем томе: сначала измените пароль роли внутри БД и согласованно обновите настройки клиентов. Команда `setup` поэтому не перезаписывает существующие значения.

## Резервное копирование

Из корня запущенного Compose:

```bash
mkdir -p backups
docker compose exec -T db pg_dump -U procurement -d procurement -Fc > backups/procurement.dump
```

Дамп содержит извлечённый текст документов. Храните резервные копии в закрытом хранилище с шифрованием. `.env` хранится отдельно от дампа. Автоматические backup-расписание, шифрование и восстановление не настроены.

Для восстановления используйте отдельную новую БД, чтобы не затереть текущие проверки:

```bash
docker compose exec -T db createdb -U procurement procurement_restore
docker compose exec -T db pg_restore -U procurement -d procurement_restore --no-owner < backups/procurement.dump
docker compose exec -T db psql -U procurement -d procurement_restore -c 'SELECT count(*) FROM "Review";'
```

После проверки отдельной БД оператор может переключить приложение на неё. Не выполняйте `docker compose down --volumes` для остановки рабочего окружения: эта команда удаляет данные.

## Диагностика

- Порт занят: остановите другой Next.js/PostgreSQL или измените привязку порта и согласованно APP_ORIGIN/DATABASE_URL.
- 403 при изменениях: адрес браузера должен совпадать с APP_ORIGIN, включая localhost/127.0.0.1, схему и порт.
- БД не готова: `docker compose logs --tail=80 db init`, затем проверьте пароль и применение миграций.
- Модель не подключена: все LLM_ENABLED, LLM_MODEL и LLM_API_KEY должны быть заполнены; процесс нужно перезапустить.
- Модель вернула ошибку: сначала проверьте совместимость Chat Completions/JSON, доступность модели и квоту. Локальный результат сохраняется.
- Потерян доступ: найдите пароль в `.local/access.txt`; при ротации меняйте ADMIN_PASSWORD и SESSION_SECRET в `.env` и пересоздавайте app.
